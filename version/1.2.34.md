# 1.2.34

## Goal
- 重写 Home 留言交流区的展示方式，把原来的静态留言列表改成实时弹幕留言板。
- 去掉留言发布成功提示，只保留失败反馈，避免重复打断浏览。

## Modified Files
- `src/components/GuestMessageBoard.tsx`
- `src/components/Home.tsx`
- `version/1.2.34.md` (new)

## Changes
- `src/components/GuestMessageBoard.tsx`
  - 保留原有消息加载、昵称校验、提交到 `/api/messages`、本地更新最近 24 条消息的业务逻辑。
  - 移除“留言发布成功”文本提示，提交成功后只清空输入框并立即把新留言加入弹幕流。
  - 新增多轨弹幕渲染逻辑，按消息内容和索引生成不同速度、延迟和配色的弹幕项。
  - 增加 `prefers-reduced-motion` 兼容：用户偏好减少动态时，自动降级为静态卡片列表，避免可访问性问题。
  - 输入区改成“广播面板”样式，保留昵称输入、留言输入、错误提示和发送按钮。
  - 展示区加入玻璃质感、渐变光斑、扫描线背景和最近一条留言摘要，整体风格更贴近 Kuromi 首页氛围。

- `src/components/Home.tsx`
  - 更新留言交流区说明文案，明确当前为实时弹幕留言板。
  - 同步状态提示文字，改成最近 24 条留言即时渲染的描述。
  - 未修改留言接口、用户权限和管理员入口逻辑。

## Preserved Behavior
- 访客模式仍然只依赖昵称，不新增注册流程。
- 留言仍然写入 Redis，接口路径与后端协议未变化。
- 最近消息条数上限仍为 24。
- 留言失败时仍然向用户显示错误信息。

## Security / Maintainability
- 未新增第三方依赖，继续复用项目已有的 `framer-motion`、`animate.css`、shadcn 风格组件。
- 保持输入内容通过后端现有校验处理，前端未绕过任何限制。
- 新增弹幕逻辑集中在单组件内部，没有侵入后端或全局状态。
