# 2.0.3

## 本次目标

再次审查所有和数据库有关的请求与响应链路，确保前端在 Ubuntu + Nginx 部署后，能够正确访问后端 API，并由后端稳定连接 Redis。

## 本次修改

### 1. `server.ts`

- 新增 `dotenv/config`，允许生产环境直接读取 `.env` 或系统环境变量。
- Redis 连接地址不再写死为本机固定密码地址，改为优先读取：
  - `KUROMI_REDIS_URL`
  - `REDIS_URL`
- 默认回退值改为 `redis://localhost:6379`，避免把敏感密码硬编码进源码。
- `PORT` 改为支持环境变量，默认仍为 `3000`。
- 新增 `NODE_ENV` / `IS_PRODUCTION`，区分开发与生产逻辑。
- 新增 `app.set("trust proxy", true)`，适配 Nginx 反代。
- 新增可选跨域白名单：
  - `KUROMI_ALLOWED_ORIGINS`
  - 逗号分隔多个来源
- 新增 `/api/health` 健康检查接口，返回：
  - `success`
  - `service`
  - `env`
  - `redisReady`
  - `timestamp`
- 新增 `/api` 级 Redis 就绪检查：
  - 当 Redis 未连接完成时，数据库相关接口统一返回 `503`
  - 响应信息会明确提示检查 Redis、环境变量和 Nginx 反代配置
- 生产环境下如果 Redis 启动连接失败，服务直接退出，避免前端拿到一个“看起来活着、实际上数据库不可用”的假服务。
- Redis 启动日志改为掩码输出，不再把密码打印到日志里。

## 审查结论

### 前端请求链路

- 前端数据库/API 相关请求已统一经过 `resolveApiUrl()`。
- 如果使用同域 Nginx 反代，前端可直接请求 `/api/...`。
- 如果前后端分域部署，前端构建前必须设置：
  - `VITE_KUROMI_API_BASE_URL`

### 后端数据库链路

- 管理员注册、管理员登录、访客登录、留言、帖子、评论等接口都依赖 Redis。
- 这些接口现在会在 Redis 未就绪时直接返回 `503`，不会再进入模糊的业务失败分支。
- 上传接口 `/api/uploads/images` 保持可用，但最终发帖仍依赖 Redis。

### Ubuntu + Nginx 运行要求

部署时不能只上传 `dist/` 静态文件，还必须同时运行 `server.ts` 对应的 Node 服务，否则：

- `/api/login`
- `/api/guest-login`
- `/api/messages`
- `/api/posts`

这些请求都会在 Nginx 静态站点上返回 `404`，前端自然无法登录，也无法访问 Redis。

## 推荐环境变量

```bash
NODE_ENV=production
PORT=3000
KUROMI_REDIS_URL=redis://:你的Redis密码@127.0.0.1:6379
KUROMI_ALLOWED_ORIGINS=https://你的前端域名
```

如果你采用前后端分域部署，前端构建前还需要：

```bash
VITE_KUROMI_API_BASE_URL=https://你的API域名
```

## 推荐 Nginx 反代

如果你采用同域部署，建议让 Nginx 这样反代：

```nginx
server {
    listen 80;
    server_name your-domain.example;

    root /var/www/kuromi/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
