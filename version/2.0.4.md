# 2.0.4

## Goal

This release adds deployment-facing documentation and container orchestration so the project can be started with Docker Compose on Ubuntu more directly.

## Changes

### `README.md`

- Rewrote the README from scratch in clean UTF-8 text.
- Added a clear project overview, stack summary, repository structure, API list, environment variables, Docker Compose usage, Ubuntu + Nginx notes, manual verification checklist, and security notes.
- Clarified that the site has no public registration system and only supports:
  - administrators `RobinElysia` and `Meow`
  - guest nickname mode

### `Dockerfile`

- Added a multi-stage Docker build for the app service.
- Build stage runs `npm install` and `npm run build`.
- Runtime stage starts `server.ts` in production mode and serves both:
  - built frontend from `dist/`
  - backend API from Express
- Added an app health check against `/api/health`.

### `docker-compose.yml`

- Added a full-stack Compose file with two services:
  - `kuromi-app`
  - `kuromi-redis`
- Redis configuration now includes:
  - external port mapping `6379:6379`
  - fixed password `000745012010psQ`
  - append-only persistence
  - snapshot persistence
  - auto restart
  - persistent named volume
- App service configuration now includes:
  - port mapping `3000:3000`
  - dependency on healthy Redis
  - `KUROMI_REDIS_URL`
  - bootstrap secrets
  - uploads volume persistence

### `.dockerignore`

- Added a minimal Docker ignore file to reduce build context noise.

## Validation

- `npm run build`: passed
- Docker syntax was reviewed manually against the current repository layout
- `npm run lint`: not rerun for this change set; the project already has an existing dependency declaration issue in `@vitejs/plugin-react`
