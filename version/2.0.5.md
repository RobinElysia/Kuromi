# 2.0.5

## Goal

Stabilize the mobile dark presentation so system theme switching no longer causes unintended text color changes on a site that is intentionally fixed to a dark Kuromi-style UI.

## Changes

### `index.html`

- Added `<meta name="color-scheme" content="dark" />` so browsers know the document is a dark-first interface before CSS finishes loading.
- Added `<meta name="theme-color" content="#020617" />` to keep the surrounding mobile browser chrome aligned with the site's dark palette.

### `src/index.css`

- Declared `color-scheme: dark` at `:root` to stop mobile browsers from auto-adjusting form controls, scrollbars, and browser-provided UI toward light mode when the OS theme changes.
- Added shared `--app-bg` and `--app-text` tokens for a stable global dark background and foreground color.
- Applied the global dark background to `html` and `body`.
- Applied the global foreground color to `body`.
- Forced `button`, `input`, `textarea`, and `select` to inherit the intended text color so mobile theme changes do not drift control text away from the site's dark styling.

## Validation

- `npm run lint`: failed on pre-existing repository TypeScript issues unrelated to this change, including existing errors in `server.ts`, `src/components/ui/badge.tsx`, `src/components/ui/tabs.tsx`, and historical component usage sites
- Scope review: only document-level theme declarations and global color inheritance were changed; no login, guest nickname, post, comment, or upload business logic was modified
