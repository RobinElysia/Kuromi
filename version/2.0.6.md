# 2.0.6

## Goal

Restore Vite startup after the local `framer-motion` package installation exposed a broken ESM entry path.

## Changes

### `vite.config.ts`

- Added an exact Vite resolve alias for `framer-motion`.
- Redirected the package import to `node_modules/framer-motion/dist/cjs/index.js`, which exists in the current installation.
- Avoided touching React page components or animation business logic; all existing `framer-motion` imports remain unchanged.

## Validation

- Root cause review: the installed `framer-motion` package declares `dist/es/index.mjs`, but that file is missing in the current local install
- Compatibility strategy: Vite now resolves to the package's existing CJS entry, bypassing the broken ESM export declaration during dependency scanning
- Direct entry check: `node_modules/framer-motion/dist/cjs/index.js` exports `motion`, `AnimatePresence`, and `useReducedMotion`
- `npm run build`: blocked in the current environment by `Error: spawn EPERM` while Vite/esbuild tries to start its worker process, so full build verification could not be completed here
